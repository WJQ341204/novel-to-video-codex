# 同类「整线产品」对比调研（2026-09）

> 调研对象：novel-to-video-codex（墨影流光 / LuminaForge）
> 现状：小说 → 分镜 → SDXL 关键帧（RealVisXL V4.0）→ Wan2.2-TI2V-5B 图生视频 → StepFun 配音 → ffmpeg 合成，**全程本地、8GB 显存**。
>
> 与 `docs/MANJU_ECOSYSTEM_RESEARCH.md` 的分工：
> - 那篇 = **能装进来的 skill / ComfyUI 插件**（ComfyUI-Novel-Director、Dramake、TE_MAN…）
> - 本篇 = **同类整线产品的形态与架构**（DramaClaw、Toonflow、火宝、waoowaoo…），看别人怎么组织流水线、在哪一层做一致性
>
> ⚠️ Star 数变动极快（同一批项目在 1–2 个月内的两篇资料里差了 30%+），下表给的是**检索时量级**，只用来判断热度/活跃度，不要当精确值。

## 一、一句话定位差

**所有主流同类产品 = 「编排器 + 云 API」，模型不在本地跑。本项目 = 「本地 8GB 显卡真跑模型」。**

DramaClaw 的 README 把这点写得很直白：所有推理走远程 OpenAI 兼容网关，**本机不需要 GPU**（标准流程），依赖只有 ~2 vCPU / 4GB，状态存 SQLite + 文件，不碰 Postgres/Redis/Celery/Ray。

所以这是两种完全不同的物种：

| | 它们 | 本项目 |
|---|---|---|
| 算力 | 云端（火山/Seedance、MiniMax、Vidu、可灵、自有网关） | 本地 8GB 显卡 |
| 成本模型 | 按次付费，出片快、画质上限高 | 一次性硬件，边际成本≈电费，但受显存钳制 |
| 隐私 | 稿件要出网 | **稿件不出机**（这是真优势） |
| 画质上限 | 1080p / 长镜头 / 首尾帧 | 首帧 i2v、短镜头、需 xfade 补尾帧 |

**结论：不要去抄它们的云网关架构，那会自废武功；要抄的是它们的「流程组织」和「一致性层」——这两样跟算力无关，纯工程。**

## 二、横向对比

### 1. 最像本项目的：DramaClaw（约 6.1k★，Elastic License 2.0，Python）

源码可见的「工业化短剧生产线」，团队自用产出了《归灵司》《鲁班》等六部短剧。12 步流水线分四阶段 **Ingest → Plan → Produce → Deliver**：

- **小说解析与故事图谱**：抽角色、人物关系、时间线，建成可查询图谱（明确说不需要知识图谱/embedding）
- **资产库与身份一致性（虾塘）**：角色 / 场景 / 道具 / **声线** 四类资产统一管理，跨集锁死形象与音色，生成角色肖像 + 单集变体
- **分集规划与叙事节奏**：自动章节切分、beat 规划、跨集叙事弧
- **剧本生成三种模式**：adaptive（网感重写）/ literal（忠于原作）/ staged（舞台化），带审校 + 修复回路
- **分镜与首帧**：beat 驱动、网格切分、**图池选优**、内置线稿草图系统
- **配音**：情感化语音合成，默认 IndexTTS2，可切换多家 TTS
- **视频合成导出**：成片 + 字幕 + 完整资产包
- 附加：无限画布（虾画，18 种节点）、导演世界 3GS（图→3D 高斯 + 全景，锁空间/机位）、AI 导演助理（虾导）、风格模板（虾格，传参考图抽风格参数全片套用）、任务中心（虾条，断点续跑 + 取消/重试）

**许可提醒**：Elastic License 2.0 — 可免费跑、改源码、卖你做出来的片子，**但不能转售成托管 SaaS**。

### 2. Toonflow（约 6.3k–13.5k★，TypeScript + Electron）

小说秒变短剧/漫剧，自动提角色 → 剧本 → 图片 → 视频。三层 Agent 协作，**无限画布工作台**，桌面版支持 Win/Mac/Linux。角色一致性口碑较好。
（许可有分歧：一处记为 Apache-2.0，另一处记为 AGPL-3.0——**装前务必核对仓库 LICENSE**，AGPL 对闭源分发不友好。）

### 3. 火宝短剧 huobao-drama（约 10k–13.8k★，Nuxt3 + Hono + Mastra Agents）

一句话生成完整短剧：剧本 → 角色形象 → 分镜 → 图生视频 → 配音字幕 → FFmpeg 合成 → 导出 MP4。内置 5 个 Mastra AI Agent，Docker 一键部署，支持火山/Seedance/MiniMax/Vidu。**门槛最低，新手首选**。

### 4. waoowaoo / Waoo（约 11k–13.5k★，Next.js 15 + MySQL + Redis + BullMQ）

工业级全流程 AI 影视生产平台，专攻**网文改编**：自动解析人物关系/场景/剧情节点 → 一致性角色场景图 → 分镜 → 多角色配音 → 成片。支持「7×24 本地 AI 短剧工厂」+ NAS 私有化部署。
注意两点：架构偏重（MySQL + Redis + BullMQ 队列）；公认「工具完成 80%，剧本质量需人工微调」。

### 5. 魔因漫创（4k+★，桌面端）

生产级桌面工具，深度对接 Seedance 2.0。剧本/角色/场景/分镜/批量视频自动衔接，**多任务并行 + 风格统一 + 角色锚点防漂移**。适合量产多集/番剧。

### 6. SkyReels-V1（昆仑万维）

不是工具而是**模型**：全球首个以人物为中心的视频基础模型，1080p 60 帧，单次 180 秒。组件拆得很清楚：SkyScript（剧本大模型）/ StoryboardGen（分镜大模型）/ Sky3DGen / WorldEngine。**参考价值在「分镜也用专门模型」这个思路**，不在可直接部署。

### 7. FastMovie（MIT，但商用版收费）

开箱即用：剧本 → 场景连贯 → 角色一致性 → 多角色对话 → 合成 → 配音字幕。免费开源版 720P；优享版 ¥19,800/年，源码版 ¥29,800/套。

## 四、本项目最值得抄的 5 件事（按投入产出排序）

### ① 把「资产库 + 一致性」从半成品推进主线 —— 最高优先级

**现状（已核实）**：
- `scripts/build_asset_bank.py` 已能生成角色定妆照 + 药铺场景参考
- `scripts/gen_assetlock_keyframes.py` 已实现 IPAdapterFaceID（脸）+ IPAdapter（场景），有脸的镜走双参考、无脸细节镜只走场景
- `scripts/train_sdxl_lora_ykf.py` 已有 SDXL 场景 LoRA 训练（diffusers+PEFT，8GB 友好：fp16 + 梯度检查点 + 512×768）
- `scripts/diag_consistency.py` 已有一致性诊断
- **但**：`scripts/novel_video.py` 文件头写着「纯 txt2img + RealVisXL（**无 IPAdapter，避免人脸参考污染**）」——资产链做完了，主线却整段绕开它。

**建议**：
1. 建 `assets/cast.json`，四类资产统一收口：角色（定妆照 + 文本锚点 token + seed 段）、场景、道具、**声线**
2. 主线从「纯 txt2img」升级为「txt2img + IPAdapter（**权重先压到 0.55–0.65**，别用资料里常见的 0.8，那正是你踩过的污染区间）+ 固定 seed 段 + 锚点 token」
3. `diag_consistency.py` 从「事后诊断脚本」提升为**出图后门禁**：不合格直接重出
4. 角色 LoRA 作为第二阶段（10–40 张、1024 分辨率、lr≈1e-4、权重 0.6–0.8）；IP-Adapter 在大角度/极端光下会弱，可保留 ReActor/InstantID 换脸兜底
5. 多人同框沿用「先单后双」

### ② 声线资产化 —— 半天工作量，立刻止血

**现状（已核实）**：`story2/dialogue.json` 里已经有 `"voices": {"wang": {"ref_wav": ...}, "narration": ...}` 这样的角色→音色映射；但主线 `scripts/add_stepfun_tts.py` 是**硬编码字典** `FIGHT_DLG = {101: ("cixingnansheng","得意",7), ...}`。两边各写各的。

**建议**：把声线并进 `assets/cast.json`，与角色同一份数据（角色 → voice / mood / intensity / 语速），主线改成查表。这样新增角色不用改代码。

### ③ 断点续跑 —— 治「一堆一次性救火脚本」

**现状**：本轮为了救 scene 101，专门写了 `complete_fight101.py`（带"等队列清空"守卫）。这类一次性脚本在 `scripts/` 里已经有一大批，是**缺状态机的症状**。

**建议**：加 `run_state.json`，每镜记录 `status: pending/done/failed` + 产物路径 + 参数哈希 + 重试次数；重跑自动跳过已完成，失败可单镜重来。`novel_video.py` 已有的 `--only` / `--compose` 就是现成的入口，补上状态文件即可（DramaClaw 的「虾条」做的正是这件事）。

### ④ 图池选优 —— 低成本、高收益

同类普遍做法是每镜出 3–4 个候选，再打分/人工挑，满意才写回主线。**本项目现在是"出一版就用"**。加一层候选池 + 简单打分（清晰度 + 与定妆照的人脸相似度），出片稳定性会有肉眼可见的提升。

### ⑤ 首帧+尾帧：别硬做，要么换模型要么写清边界

本机 Wan2.2-TI2V-5B 是**首帧-only**，无法条件化尾帧；真正的首尾双关键帧要 FLF2V。当前用 ffmpeg `xfade` ~0.8s 落尾帧是可接受的降级方案，但**应在文档里明确标注为降级**，别让人以为是原生首尾帧。后续若装 FLF2V 再切换。

## 五、明确**不要**抄的

| 别人的做法 | 为什么不抄 |
|---|---|
| 云网关架构（DramaClaw / 火宝 / Toonflow） | 会把「本地、稿件不出机」这个唯一硬优势丢掉 |
| 导演世界 / 3GS（图→3D 高斯 + 全景） | 8GB 显存跑不动，且本机流程用不上 |
| MySQL + Redis + BullMQ（waoowaoo） | 单机 8GB 场景是纯粹负担；SQLite + 文件就够 |
| 无限画布 18 种节点 | 工程量巨大，先把主线跑顺，画布是锦上添花 |

## 七、待你拍板的两件事

1. **资产库主线化**要不要现在动手？我建议先做最小一步：`assets/cast.json` + `add_stepfun_tts.py` 查表（半天），图的部分（IPAdapter 权重调优 + 门禁）单开一轮，因为它需要反复试权重。
2. **青囊异闻录**目前无台词 → 成了纯字幕默片。三个选项：(a) 给老者/叶玄机写台词并配音；(b) 保持默片；(c) 允许它作为例外保留旁白配音。
