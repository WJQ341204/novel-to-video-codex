## 1. 系统概览

小说文本 → 分镜与角色锚定 → 首帧图 → 图生视频 → 配音字幕 → 合成成片 → 出库。

三种运行形态：

1. **桌面应用**（主要形态）：`scripts/launcher.py` 自动拉起 ComfyUI、CosyVoice2 与 FastAPI 主服务，并打开浏览器访问 `http://localhost:8190`。
2. **Web 服务**：`python scripts/main.py` 直接起 FastAPI（8190）。
3. **命令行出片主链**：`python scripts/flow.py`（预检 → 渲染 → 配音 → faststart → 报告）。

## 3. 后端

### 3.1 技术栈

- 语言：Python（`requirements.txt` 固定版本）
- Web：**FastAPI 0.115.6** + **uvicorn 0.34.0**（`uvicorn.run(app, host="0.0.0.0", port=8190)`）
- 数据校验：Pydantic（`app/models.py`）
- 异步/网络：`httpx`、`websockets`
- 音频：`edge_tts`、`pydub`
- 桌面打包：PyInstaller（`luminaforge.spec`，入口 `scripts/launcher.py`）

### 3.2 核心流水线

**命令主链**（`scripts/flow.py`）：

```
1 预检 → 2 渲染(scripts/novel_video.py) → 3 配音(scripts/add_stepfun_tts.py)
       → 4 faststart（moov 前置）→ 5 报告
```

**API 驱动全流程**（`scripts/main.py`）：上传小说 → 角色分析 → 分镜 → 提示词 → 首帧 → 视频 → 配音 → 合成 → QA → 导出。

### 3.3 引擎抽象与路由

所有引擎实现同一接口（`engines/base.py`）：

- `GenerateRequest`：prompt / first_frame / last_frame / width / height / duration / fps / seed / reference_images / negative_prompt / output_dir / output_name / task_id / max_cost_usd / **`task_type`** / **`generate_audio`** / **`audio_prompt`**
- `ClipResult`：video_path / engine / cost_usd / duration / seed / task_id / model / quality_report / downgraded_from / **`audio_path`**
- `BaseEngine`：`name` / `kind`（cloud\|local\|hybrid）/ `capability`（i2v\|t2v\|both）+ `generate()` / `is_available()` / `estimate_cost()`

路由（`engines/registry.py`）按 `settings.yaml` 的 `local_kind` 选择：

| `local_kind` | 引擎 | 模型 | 现状 |
| --- | --- | --- | --- |
| **`wan5b`** | `Wan5BEngine` | Wan2.2-TI2V-5B | ✅ **当前生产** |
| `wan` | `WanEngine` | Wan2.2-I2V-A14B（双专家 MoE） | ✅ 备用 |
| `comfyui` | `ComfyUIEngine` | LTX-2.3-22B | ✅ 备用 |
| `h3_ascend` | `H3AscendEngine` | MiniMax H3（自托管） | ✅ 已接入，需服务器 |

云端引擎（`seedance_ark` / `kling_official` / `minimax` / `runway` / `veo` …）在 `priority` 列表中，但 `video_mode: local`，**当前不会调用**。

### 3.4 模型清单（当前生效）

| 环节 | 模型 | 文件 | 关键参数 |
| --- | --- | --- | --- |
| 视频生成 | **Wan2.2-TI2V-5B** | `Wan2.2-TI2V-5B-Q5_K_M.gguf` | 672×1152、65 帧、24fps、quality=high |
| ├ VAE | Wan2.2 VAE | `Wan2.2_VAE.safetensors` | bf16 |
| ├ 文本编码器 | UMT5-XXL | `umt5-xxl-enc-fp8_e4m3fn.safetensors` | fp8 |
| └ 补帧 | RIFE 4.7 | `rife47.pth` | — |
| 首帧图 | **SDXL** | `RealVisXL_V4.0.safetensors` / `animagine-xl-4.0.safetensors` | 见 `scripts/agent_image.py` |
| 配音 | **StepFun**（主） / Edge-TTS / CosyVoice2（本地 50000） | — | 声线查 `assets/cast.json` |

> 8GB 显存约束：配置注释明确 `960×1728×96帧` 会 staging ~23GB/170s每步而卡死，故降为 `672×1152×65帧`。

**分镜与生成**

### 3.6 H3 自托管引擎（新增，昇腾 910B）

- 入口：`engines/h3_ascend.py`，`kind=hybrid`，自托管不计费（`estimate_cost` 恒 0）
- 配置：`H3_ASCEND_URL` / `H3_ASCEND_TOKEN` / `H3_ASCEND_MODEL` 环境变量；`local_kind: h3_ascend` 启用
- **未来接口（omni 特性，已接好）**：
  - `task_type` 路由：`t2va` / `fl2va` / `ref2va`，按首帧/参考图真实存在自动推断，可显式覆盖
  - 原生同步音频：`generate_audio=True` 时请求并抽取，落盘 `<name>_h3audio.<ext>`，经 `ClipResult.audio_path` 暴露
  - `ref2va` 参考图 base64 内联
- 响应解析对 `video/audio/url/b64` 多字段名宽松兼容，**待真机 schema 校准**
- 校准工具：`scripts/h3_schema_probe.py`（零依赖，抓真实 openapi schema；`--generate` 才发推理请求）
- 部署指南：`docs/H3_ASCEND_DEPLOY.md`；启动脚本：`scripts/deploy_h3_ascend.sh`

### 3.7 配置

- 实际生效配置：**仓库根 `settings.yaml`**（`video_mode: local`、`local_kind: wan5b`、`672×1152`、`frames: 65`、`fps: 24`）
- 配置模型与默认值：`config/settings.py`（Pydantic，无 YAML 时用默认值；默认 `local_kind` 为 `comfyui`，**注意与实际 settings.yaml 不一致**）

### 3.8 关键工程约束

- **确定性种子**：用 `zlib.crc32` 派生，禁用 Python 内置 `hash()`（跨进程加盐会导致关键帧不可复现）
- **faststart**：成片必须 `moov` 前置才能边下边播；`flow.py` 第 4 步统一处理
- **断点续跑**：`output/novel_demo_v2/run_state.json`（参数指纹 + 产物路径，<5KB 视为半成品）
- **出库前备份**：写盘前先 `backup_if_exists`
- **`output/` 不入库**：被 `.gitignore` 排除（约 1GB 中间产物）
- **ffmpeg/ffprobe**：不在 PATH，使用绝对路径

### 4.2 目标：Nuxt + Iconify + Node.js 🚧（规划）

> 本节为**目标架构 / 迁移方案**，代码尚未创建。

#### 技术选型

| 项 | 选型 | 说明 |
| --- | --- | --- |
| 运行时 | **Node.js 20 LTS+** | Nuxt 3/4 要求；与 `package.json` 中 `@types/node` 保持兼容 |
| 框架 | **Nuxt 3 / 4**（Vue 3） | 文件路由、SSR/SSG、内置 `$fetch` 与 `useFetch` |
| 组件 | **Vue SFC + components 目录** | Nuxt 自动导入组件 |
| 图标 | **Iconify**（`@nuxt/icon` 官方模块 + `@iconify/vue`） | 替换现状 lucide-react |
| 状态 | Pinia | 对应现状 Zustand |
| 数据请求 | `$fetch` / `useFetch`（可加 `@tanstack/vue-query`） | 对应现状 react-query |
| 样式 | Tailwind CSS（`@nuxtjs/tailwindcss`） | 与现状一致，降低迁移成本 |
| 包管理 | npm / pnpm | 与现状 `package-lock.json` 二选一，建议统一 |

#### 建议目录结构

```
nuxt-app/
  app.vue
  nuxt.config.ts          # 模块：@nuxt/icon、@nuxtjs/tailwindcss；runtimeConfig 代理
  components/             # 自动导入的业务组件
  layouts/                # default.vue（对应 AppLayout）
  pages/                  # 文件路由：projects / characters / storyboard / generate / export
  composables/            # useApi / useJobProgress / useWebSocket（对应 hooks/）
  stores/                 # Pinia（对应 stores/）
  types/                  # 对应 lib/types.ts
  assets/css/             # Tailwind 入口
  public/
```

#### 图标方案（Iconify）

- 安装 `@nuxt/icon`（官方 Nuxt 模块，底层 Iconify）+ 需要的图标集 `@iconify-json/<collection>`（如 `lucide`、`mdi`、`carbon`）
- 用法：`<Icon name="lucide:video" />`（Nuxt Icon 组件）
- **在线 vs 离线**：默认走 Iconify 公共 API；内网/离线环境安装 `@iconify/json` 或指定 `@iconify-json/*` 本地集合，并在 `nuxt.config.ts` 配置 `icon.serverBundle.collections`，避免运行时外网依赖
- **从 lucide-react 迁移**：`lucide:xxx` 集合与原 lucide 图标名基本一一对应（如 `Video` → `lucide:video`），可批量替换；建议先建立图标名映射表再改组件

#### API 与实时进度对接

- REST：用 `$fetch` / `useFetch` 打 `/api/*`（dev 代理到 8190，生产同源或反向代理）
- WebSocket：在 composable 中封装 `ws://<host>/ws/progress/{job_id}`，对应现状 `useWebSocket.ts` / `useJobProgress.ts`
- `nuxt.config.ts` 代理示例：

```ts
export default defineNuxtConfig({
  modules: ["@nuxt/icon", "@nuxtjs/tailwindcss"],
  devServer: { port: 3000 },
  nitro: {
    devProxy: {
      "/api":    { target: "http://localhost:8190", changeOrigin: true },
      "/ws":     { target: "ws://localhost:8190", ws: true },
      "/output": { target: "http://localhost:8190", changeOrigin: true },
    },
  },
})
```

#### 组件划分（对应后端能力）

| 页面/组件 | 对应后端接口 |
| --- | --- |
| 项目创建 / 上传 | `/api/create-job`、`/api/upload-novel`、`/api/upload-text` |
| 角色面板与音色 | `/api/analyze-characters`、`/api/update-character-voice`、`/api/tts-voices`、`/api/preview-tts` |
| 分镜与提示词 | `/api/generate-storyboard`、`/api/generate-prompts`、`/api/jobs/{id}/prompts` |
| 生成控制台 | `/api/start-generation`、`/api/cancel-generation`、**WS 进度** |

#### 迁移路径建议（React+Vite → Nuxt）

1. **并存过渡**：Nuxt 应用独立目录，接入同一套 8190 API，与现状 `web/` 并行跑，按页面逐个切换
2. **逐层替换**：`hooks → composables`、`Zustand → Pinia`、`react-query → useFetch/vue-query`、`lucide-react → Iconify`
3. **风险点**：图标名映射、WebSocket 生命周期（Vue 的 `onUnmounted` 对应 React `useEffect` cleanup）、SSR 下浏览器 API（WebSocket 需 `onMounted` 或 `client-only`）
4. **验收**：先切一个低风险页面（如设置/关于），跑通再推进核心生成流程

## 5. 端到端数据流（典型一次出片）

```
用户上传小说 (POST /api/upload-novel)
   → 角色分析 (POST /api/analyze-characters)
   → 分镜生成 (POST /api/generate-storyboard)
   → 提示词生成 (POST /api/generate-prompts)
   → 首帧图：SDXL 经 ComfyUI(8188) 出图
   → 视频：Wan2.2-TI2V-5B 经 ComfyUI i2v
        └ 进度经 ws://8190/ws/progress/{job_id} 推送前端
   → 配音：StepFun / CosyVoice2(50000) 合成台词音频
   → 合成：字幕 + 音频 + 视频合并
   → QA (POST /api/qa-test) 与修正 (POST /api/qa-fix)
   → faststart 处理 → 导出 (GET /api/jobs/{id}/export)
```

## 8. 已知约束与风险

| 约束 | 说明 |
| --- | --- |
| 8GB 显存 | 必须 `672×1152×65帧`；更大会卡死。H3（33B）无法在此机器运行 |
| 权重不通用 | Wan2.2-TI2V-5B 与 MiniMax-H3 权重不可复用；H3 需单独拉取（FL2VA ≈135–144GB） |
| 配置双源 | `config/settings.py` 默认值（`comfyui`）与根 `settings.yaml`（`wan5b`）不一致，**实际生效的是 settings.yaml** |
| H3 schema 待校准 | 视频/音频响应字段名需按真机 OpenAPI 校准（`scripts/h3_schema_probe.py`） |
| 前端图标迁移 | lucide-react → Iconify 需建立映射表；离线环境须装本地图标集合 |
| `output/` 不入库 | 1GB 中间产物被 gitignore，协作时不能依赖仓库恢复中间态 |
| 成片入库 | 成片只以 `films/` 形式入库（12 支命名成片 + 分镜帧 PNG + 演示页） |

**术语**

- **i2v / t2v**：图生视频 / 文生视频
- **t2va / fl2va / ref2va**：H3 任务类型（文生视频音 / 首帧生视频音 / 参考图生视频音，"A" = Audio）
- **faststart**：mp4 的 `moov` box 前置，支持边下边播
- **local_kind**：本地引擎选择开关（`settings.yaml`）
