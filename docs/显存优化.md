## 二、本次新增的三件事

### 1. `scripts/vram_opt.py` —— 显存助手

```bash
python scripts/vram_opt.py stats       # 打印 GPU + ComfyUI + 队列状态
python scripts/vram_opt.py free        # 请求 ComfyUI 卸载模型并回收显存
python scripts/vram_opt.py preset low  # 打印 low 档推荐参数
```
`free()` 带保护：队列里还有任务在跑时会跳过，不会打断出片。

### 2. 块交换深度可调（`LF_BLOCKS_SWAP`）

`engines/wan5b.py` 的 `blocks_to_swap` 不再写死，改读环境变量（默认 30，失败自动回落）：

```bat
set LF_BLOCKS_SWAP=40
python scripts/flow.py --cast --style --neg base,face
```

### 3. 每幕之间自动回收显存

`scripts/novel_video.py` 每幕开始前调一次 `vram_opt.free()`——多幕连跑时防止上一幕的模型驻留造成碎片堆积。
`scripts/flow.py` 预检阶段增加显存现状打印，出片前先看一眼余量。

## 三、三档预设

| 档位 | blocks | 建议分辨率 | 说明 |
|---|---|---|---|
| normal | 30 | 1280×704 | 默认，画质优先 |
| low | 40 | 1024×576 | 省约 1GB，画质轻微下降 |
| ultra | 48 | 832×480 | 极限省显存，分辨率明显下降 |

> 分辨率需由调用方决定，预设只给建议值；块数通过 `LF_BLOCKS_SWAP` 生效。
> **越大越省显存、但越慢**——块交换是把 Transformer 块在 CPU/GPU 间搬，速度换空间。

## 四、OOM 排查顺序

1. 先看余量：`python scripts/vram_opt.py stats`
2. 调大块交换：`set LF_BLOCKS_SWAP=40`（还不行就 48）
3. 降分辨率：1280×704 → 1024×576 → 832×480
4. 降帧数（效果最猛）：帧数直接决定 latent 的时间长度
5. 多幕连跑仍崩 → 确认每幕之间的 `free()` 生效（日志里有"已请求 ComfyUI 卸载模型"）

## 五、ComfyUI 启动参数建议

```bat
"D:\ComfyUI\venv\Scripts\python.exe" main.py --lowvram --reserve-vram 2 --port 8188 --listen 127.0.0.1
```
- `--reserve-vram 2`：为系统/UI 预留 2GB；显存极紧时可调到 1，但别低于 1（容易整机卡死）。
- 不加 `--lowvram` 在 8GB 上必 OOM，别摘。
